# 0.3.2 保存程序到 Flash

验证日期：2026-10-11。使用 Java 25、Gradle Wrapper 9.8.1、IntelliJ Platform Gradle Plugin 2.19.0 和 IDEA 2026.2 SDK。开发机未安装厂商 ACS SDK/ADK，控制器测试使用 Java 模拟传输和测试导出 C 库。

## 变更与范围

- 控制器工具窗口增加独立的 **保存到 Flash** 按钮，操作编辑器当前文件映射的缓冲区。
- 确认框显示环境、连接目标、文件、缓冲区及覆盖后下次上电加载的影响。有 Debug 会话时要求先停止调试；正在处理请求时拒绝提交。
- 引擎复用源码与编译检查：必须有本次连接的成功编译记录，源码符合 ASCII，文件、缓冲区映射及控制器上传内容一致，状态为已编译或已终止。运行、暂停、编辑、空、未编译、未知状态均拒绝保存。
- 仅发送 `#SAVEPROG <编号>`，不省略编号，不调用整体保存、参数保存、D-Buffer 保存、运行或重启。普通连接、下载编译及执行不会自动保存到 Flash。
- 使用已有 `acsc_Transaction` SDK 通道，未增加 SDK 导出函数。保存超时/断线后关闭连接，不自动重试；丢失回复不能证明 Flash 写入失败。控制器保护错误照常显示，不自动解除保护。

手册与接口的依据、单缓冲区语法的版本限制及使用步骤见[控制器指南](controller.md)。本地 3.12 手册确认 `#SAVEPROG` 的存在；具体单缓冲区参数参考 ACS 早期文档，真实 3.12 SDK 接受情况仍待验证。

## 自动验证

全部 **64 项测试通过**，失败、错误、跳过均为 0：原有语言编辑测试 33 项，控制器引擎/协议测试 23 项，IDE 集成测试 4 项，Windows 原生桥接测试 4 项。完整运行传入 `mockSdkDll`；普通构建没有该参数时，4 项桥接及 1 项完整 IDE 调试测试明确跳过。

新增或扩展的检查覆盖：

- 保存命令只携带一个合法数字缓冲区编号（0–63）；编译时没有 Flash 写入。
- Java 模拟传输确认仅当前缓冲区的程序快照更新，其他缓冲区的 Flash 快照保持原样，没有下载或执行指令。
- 未编译、编译失败、文件或映射变化、非 ASCII 本地/远程源码、运行/暂停等状态、未知状态均拒绝保存。
- 外部修改源码后，即使恢复原字节，仍要求重新下载编译。
- 保护错误保留原 Flash；保存完成后回执丢失的情形只发送一次保存命令，不停止、重启、整体保存或自动重试。
- Windows PowerShell → C# → x64 测试 DLL 的真实调用链使用 `#SAVEPROG 2`；快照与 ASCII 程序字节一致，后续 RAM 修改没有改变保存的快照。

测试 DLL 仅在进程内模拟 Flash 快照，不是 ACS 模拟器，也未模拟真实断电保持。`?MOCK_FLASH_*` 是测试 DLL 的检查命令，不是厂商 API；插件没有使用这些检查命令。

`buildPlugin` 和 `verifyPluginStructure` 通过。测试报告为 `build/reports/tests/test/index.html`，构建日志为 `.build-tools/flash-validation.log`。ZIP/JAR CRC、打包版本、Flash 按钮和指定缓冲区命令检查通过；厂商/测试 DLL、PDF 均未打包。全部五个演示脚本仍通过 ASCII 检查。
